# Serviter

Локальное приложение для macOS, которое **безопасно публикует статический сайт из GitHub на Ubuntu/Apache по SSH**, не заменяя чужие виртуальные хосты. Интерфейс на русском языке.

**[Проект сайта ADT Studio](https://github.com/KIBHR/cipher-breach/pull/15)** можно развернуть, указав ветку `feature/adt-studio-website` и папку `website`.

## Возможности

- Работа с публичными и приватными GitHub-репозиториями (приватный требует fine-grained PAT с доступом **Contents: Read** только к выбранному репозиторию).
- Пароль SSH или путь к приватному SSH-ключу; отдельный пароль sudo при необходимости.
- При первом соединении **нужно сверить SHA256-отпечаток хоста** с панелью VPS/уже доверенным сеансом, после чего ключ закрепляется в `~/.serviter/known_hosts`; смена ключа блокируется. Автоматического доверия случайному SSH-ключу нет.
- Из ZIP-архива извлекаются **только разрешённые статические файлы** указанной папки, без симлинков, конфигураций и секретов.
- Только отдельные `serviter-<domain>.conf`, `/var/www/serviter-sites/<domain>`, атомарная смена `current` и откат на предыдущий выпуск.
- Проверка DNS, Ubuntu, Apache, сертификата, `apache2ctl configtest` и опционально `https://api.<domain>/v1/health` **до и после**. Чужие конфигурации Apache, PHP и PostgreSQL не меняются.
- Получение HTTPS сертификата через Certbot **webroot** без остановки Apache, если сертификат ещё не существует.
- Секреты не сохраняются в конфигурационный файл, не передаются в GitHub Actions и не записываются в журнал. На VPS временная папка удаляется по завершении.

## Запуск на macOS из исходников

Установите Python 3.11+ (вариант с Tkinter), затем в терминале:

```bash
git clone https://github.com/KIBHR/serviter.git
cd serviter
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python -m serviter
```

На macOS со стандартной Homebrew-сборкой Python может потребоваться пакет `python-tk`; Python с python.org уже содержит Tkinter.

## Готовое приложение `.app`

После успешного выполнения GitHub Actions откройте **Actions → Check and build Serviter for macOS → последний успешный запуск → Artifacts → Serviter-macOS-unsigned**. Распакуйте `Serviter.app` и откройте на Mac. `.app` пока **не подписан Apple Developer ID и не нотариализован** — Gatekeeper может предупреждать. Рекомендуется запуск из проверенного исходного кода до подписывания приложения.

## Использование

1. Заполните SSH-хост, пользователя, пароль/ключ, ссылку на GitHub, ветку, папку сайта (например, `website`), домен, e-mail для Let's Encrypt, при необходимости GitHub token. Для игры используйте URL проверки `https://api.adt-studio.asia/v1/health`.
2. Нажмите **«Проверить сервер»**. При первом входе проверьте SHA256 fingerprint через доверенный канал (например, панель провайдера и команду `sudo ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub -E sha256`). Введите показанный отпечаток для явного закрепления.
3. После успешного безопасного осмотра нажмите **«Опубликовать HTTPS»**, прочтите план и подтвердите. В конце приложение проверит доступность сайта и неизменность API.
4. **«Откатить сайт»** возвращает предыдущий успешный выпуск, не затрагивая API.

Сервису на VPS нужны Ubuntu с **Apache, модулями ssl/alias/dir, Python 3 и Certbot** (при отсутствии сертификата), доступ к HTTP-порту 80 для проверки домена и возможность `sudo` для пользователя. Приложение **не выполняет `apt upgrade`, не удаляет чужие сайты, не трогает PostgreSQL**. DNS A/AAAA домена должен указывать на SSH-сервер. Если домен уже обслуживается чужим vhost, Serviter **откажется перезаписывать его**. Существующий vhost API останется нетронутым.

## Что приложение НЕ делает

- Не предназначено для запуска веб-приложений с Node.js, PHP, базами данных, контейнерами или серверной логикой: это **изолированный деплой статического сайта**.
- Не настраивает DNS у регистратора, не регистрирует домен и не гарантирует прохождения проверки Google Play.
- Не устраняет неполадки существующего Apache. При конфликте или проблеме с сертификатом процесс остановится безопасно.
- Не может гарантировать отсутствие простоев API при неисправностях VPS, общесистемной нехватке ресурсов или нестандартной конфигурации — поэтому делает проверки до и после и может откатить **свои** изменения.
- Не является сервером-хранилищем паролей. Не используйте его с не доверенными исходными репозиториями.

## Структура

```text
serviter/gui.py            GUI на Tkinter
serviter/models.py         Проверка введённых данных
serviter/source.py         Безопасное извлечение сайта из GitHub ZIP
serviter/ssh_client.py     SSH host key pinning + SFTP / sudo
serviter/remote_worker.py  Ограниченный Ubuntu/Apache установщик
serviter/deploy.py         Проверка / публикация / откат
```

### Важно о безопасности

Пароль от сервера не коммитится в репозиторий Serviter и не требуется для CI. Если пароль уже был отправлен в чат или другой внешний сервис, смените его и предпочтительно используйте SSH-ключ с отдельными правами sudo.
